# ADR-0003: 의미 기반 매칭으로 스키마 복원도를 평가하고, 세 가지 데이터셋을 조합

- 상태: 제안
- 날짜: 2026-09-30
- 결정자: 

## 상황

스키마 생성 전용 벤치마크는 드물다. 또 같은 문서에서도 타당한 스키마가 여러 개 나올 수 있고, 테이블·컬럼 이름은 정답과 다르게 생성되는 경우가 많다(`customer` 대 `client`, `cust_nm` 대 `customer_name`). 문자열 일치로 평가하면 실제로는 맞는 설계를 틀렸다고 판정하게 된다.

사용 가능한 데이터셋은 다음과 같다.

- **SQUiD** (EMNLP 2025): 텍스트에서 다중 테이블 관계형 DB를 생성하는 과제로, nlxpg와 가장 가깝다. 다만 입력이 비교적 단순한 설명문이다.
- **Doc2DB-Bench**: BIRD/Spider 기반 42개 스키마, 203개 장문 문서(평균 약 43K 토큰). 원래는 스키마가 주어지는 추출 과제지만, 정답 스키마를 숨기면 스키마 유도 평가에 쓸 수 있다. 영어 전용이다.
- **BIRD 역복원**: BIRD의 database_description 컬럼 설명을 입력 문서로 보고 스키마를 복원한다. pgxnl에서 이미 PostgreSQL로 이관해 두었다.

## 결정

1. 세 데이터셋을 조합해 평가셋을 구성한다.
2. 테이블·컬럼 매칭은 임베딩 유사도 또는 LLM 판정 기반 의미 매칭으로 정의한다.
3. 지표는 테이블·컬럼 매칭 정밀도·재현율·F1, PK/FK 일치율, 데이터 타입 정확도, DDL 실행 성공률로 한다.
4. 자동 지표와 함께 사람 검토 점수를 병행한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| 이름 문자열 완전 일치 | 단순하고 재현 가능 | 타당한 설계를 오답 처리 | 미채택 |
| 사람 검토만 사용 | 설계 품질을 가장 잘 반영 | 느리고 반복 실험에 부적합 | 미채택 |
| 의미 매칭 자동 지표 + 사람 검토 병행 | 반복 실험과 품질 판단을 모두 지원 | 매칭 판정 자체의 오류 가능성 | **제안** |

## 결과

- 1단계(평가 기반 구축)에서 매칭 로직을 먼저 만들고, 소량의 수작업 판정과 비교해 매칭 정확도를 확인해야 한다.
- LLM 판정을 쓰는 경우 판정 모델과 프롬프트를 고정해 점수의 재현성을 유지한다.
- 한국어 평가는 Doc2DB-Bench의 공개 역합성 파이프라인으로 한국어 문서를 생성해 보완한다.
