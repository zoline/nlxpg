# ADR-0009: 기관 추가 표준은 공통표준 원본과 분리해 시스템 DB에 두고, 원본 위에 덧붙인다

- 상태: 채택
- 날짜: 2026-10-01
- 결정자: Youngki Ku

## 상황

공통표준에 없는 단어가 문서에 자주 나온다. 예를 들어 "비행기"는 공통표준 단어가 아니고(표준은 "항공기"), 이음동의어로도 등록돼 있지 않다. 그래서 한빛항공사 예제에서 비행기 테이블과 비행기번호 컬럼이 비표준이 됐다.

공공데이터베이스 표준화 관리 매뉴얼은 기관 표준(공통표준 + 기관이 추가한 용어·단어)을 허용한다. 그렇다고 공통표준 CSV를 직접 고치면 새 판(다음 차수)을 받을 때 기관 추가분이 사라지고, 무엇이 원본이고 무엇이 추가인지도 구분할 수 없다.

## 결정

- 공통표준 CSV(`data/standards/`)는 **고치지 않는다.** 기관 추가분은 시스템 DB `nlxpg_std_local`에 따로 둔다.
- 추가할 수 있는 것은 세 가지다.
  - **이음동의어**: 기존 단어를 가리킨다. 예: 비행기 → 항공기
  - **기관 단어**: 이름, 영문약어, 영문명, 형식단어 여부, 도메인 분류를 넣는다.
  - **기관 용어**: 단어(공통·기관)를 조합한다. 영문약어는 단어 약어를 이어 만들고, 도메인은 공통표준 도메인 중에서 고른다.
- **원본이 우선이다. 추가만 한다.**
  - 공통표준에 있는 단어·이음동의어·용어와 같은 이름은 등록할 수 없다.
  - 공통표준 단어·용어와 같은 영문약어도 등록할 수 없다.
  - 기관 항목이 쓰는 단어는 지울 수 없다.
- 서버는 공통표준 CSV를 읽은 뒤 DB의 기관 항목을 덧붙여 쓴다. 관리 화면에서 바꾸면 재시작 없이 바로 반영된다.
- 기관 항목을 하나라도 써서 만든 이름은 판정을 **"기관"**(`local`)으로 따로 표시한다. 공통(`common`)·조합(`composed`)과 섞지 않는다. 표준 검증에서는 "기관 표준"으로 판정한다.
- 실행마다 그때 쓴 기관 항목 목록을 실행 설정(`config.local_standards`)에 남긴다. 나중에 항목이 바뀌어도 그 실행이 무엇을 기준으로 했는지 알 수 있다.
- 등록·수정·삭제는 **관리자만** 할 수 있다. 조회는 모든 사용자가 한다.
- CSV로 내보내고 불러올 수 있다(한 파일, `구분` 열로 종류를 나눔). 기관 표준 신청 자료나 다른 서버 이관에 쓴다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| 공통표준 CSV에 직접 추가 | 구현 없음 | 새 판을 받을 때 사라짐, 원본과 추가분 구분 불가 | 미채택 |
| 별도 CSV 파일(`data/standards/local/`) | git으로 이력 관리 | 화면 편집 불가, 바꿀 때 재시작 필요 | 미채택 |
| 시스템 DB + 관리 화면 | 화면에서 바로 반영, 모델 설정(ADR-0007)과 같은 방식, CSV 내보내기로 이관 | DB 백업에 포함해야 함 | **채택** |

## 결과

- 시스템 DB 백업에 기관 표준도 포함된다.
- 공통표준 새 판을 적용할 때 기관 항목이 새 공통표준과 충돌할 수 있다(같은 단어가 공통표준에 새로 들어온 경우). 충돌한 항목은 적용하지 않고 관리 화면에 표시한다. 그러면 관리자가 지울 수 있다.
- 기관 단어 조합 이름은 공통표준 용어가 아니다. 표준 준수율 계산에서 "표준"으로 세지 않고 "기관 표준"으로 따로 센다.
