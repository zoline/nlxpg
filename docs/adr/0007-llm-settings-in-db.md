# ADR-0007: LLM 설정은 웹 UI에서 프로필로 등록해 시스템 DB에만 저장한다

- 상태: 채택
- 날짜: 2026-10-01
- 결정자: Youngki Ku

## 상황

LLM 접속 정보를 `.env`(또는 pgxnl의 `.env`)에서 읽었다. 설치할 때 묻도록 만들었지만, LLM 유형(vLLM, watsonx CPD, watsonx IBM Cloud 등)이 많아 명령줄로 받기에 항목이 많고, 바꿀 때마다 서버 재시작이 필요했다. 설정이 비어 있으면 기본값 때문에 공개 OpenAI API를 부르는 일도 있었다. pgxnl은 이미 관리 → 모델 설정 화면에서 프로필을 등록해 단계별로 고른다.

## 결정

- LLM 설정은 **웹 UI 관리 → 모델 설정**에서 프로필로 등록하고, **시스템 DB에만** 저장한다(`nlxpg_llm_profiles`, `nlxpg_llm_roles`).
- 실행 중에는 `.env`·pgxnl의 LLM 설정을 **읽지 않는다**. `.env`에는 시스템 DB 접속과 암호화 키(`NLXPG_SECRET_KEY`)만 둔다. 기존 `.env`의 LLM 설정은 옮기지 않는다.
- 키·비밀번호는 `NLXPG_SECRET_KEY`로 Fernet 암호화한다(pgxnl과 같은 방식, `cryptography` 패키지).
- 역할: 문서 추출(필수), 테스트 문서 작성(없으면 문서 추출과 같음). 역할마다 "생각 끄기"를 정한다.
- 관리자가 처음 로그인했는데 LLM이 없으면 모델 설정 화면으로 보낸다. 처음 만든 프로필은 문서 추출에 자동 지정한다.
- 화면을 쓸 수 없는 서버는 `nlxpg setup llm`이 같은 프로필을 DB에 만든다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| `.env`에 두고 설치 때 묻기 | 의존성 없음 | 항목이 많고, 프로필을 여러 개 두기 어렵고, 바꿀 때마다 재시작 | 미채택 |
| 화면에서 고치되 `.env`에 저장 | 의존성 없음 | 서버 파일을 웹에서 고치게 되고 재시작 필요 | 미채택 |
| DB 프로필 + `.env` 폴백 | 이전 방식과 호환 | 어디서 읽었는지 헷갈림 | 미채택 |
| DB 프로필만 (암호화) | 한 곳에서 관리, 재시작 없이 바뀜, pgxnl과 같은 사용법 | `NLXPG_SECRET_KEY`를 잃으면 키를 다시 입력 | **채택** |

## 결과

- `NLXPG_SECRET_KEY`는 설치 때(또는 서버가 처음 뜰 때) 만들어진다. `.env` 백업이 필요하다.
- DB 백업에 LLM 프로필도 포함된다(키는 암호화된 채로).
- `Settings`의 `NLXPG_LLM_*`·`NLXPG_TESTDOC_LLM_*` 필드는 실행 경로에서 쓰지 않는다(프로필 값을 담는 그릇으로만 쓴다). 나중에 정리한다.
