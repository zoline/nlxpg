# ADR-0001: nlxpg 범위를 스키마 설계로 한정하고, 레코드 추출·적재는 별도 프로젝트로 분리

- 상태: 채택
- 날짜: 2026-09-30
- 결정자: Youngki Ku

## 상황

Text-to-Database는 두 가지 문제를 포함한다.

1. 문서에서 엔티티·속성·관계를 찾아 **스키마를 설계**하는 문제
2. 설계된 스키마에 문서 내용을 **레코드로 추출·적재**하는 문제

두 문제는 입력과 출력, 평가 방법이 다르다. 스키마 설계는 문서만 입력받아 DDL을 출력하고, 정답 스키마와의 구조적 일치로 평가한다. 추출·적재는 문서와 스키마를 함께 입력받아 레코드를 출력하고, 셀 단위 정확도로 평가한다. Doc2DB-Bench도 스키마가 주어진 상태의 추출 과제로 정의되어 있다.

## 결정

nlxpg는 문서 → PostgreSQL 스키마(DDL, ERD, 테이블·컬럼 설명)까지만 다룬다. 레코드 추출·적재는 별도 프로젝트로 진행한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| 하나의 프로젝트에서 스키마 설계와 적재를 함께 수행 | 엔드투엔드 결과를 빨리 보여줄 수 있음 | 범위가 커지고, 오류가 설계 단계에서 났는지 추출 단계에서 났는지 구분하기 어려움 | 미채택 |
| 스키마 설계만 수행, 적재는 별도 프로젝트 | 과제와 평가 기준이 명확함, 두 프로젝트를 독립적으로 개선 가능 | 엔드투엔드 데모는 두 프로젝트가 모두 준비된 뒤에 가능 | **채택** |

## 결과

- nlxpg의 평가는 스키마 복원도(테이블·컬럼·키 일치)에만 집중한다.
- 추출·적재 프로젝트는 nlxpg의 산출 스키마를 입력으로 받고, Doc2DB-Bench 원본을 평가셋으로 쓴다.
- 두 프로젝트 사이의 인터페이스(스키마 산출물 형식)를 명확히 정의해야 한다.
