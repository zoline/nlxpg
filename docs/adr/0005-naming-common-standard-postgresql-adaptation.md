# ADR-0005: 명명·타입은 공공데이터 공통표준을 따르고, 날짜 타입과 물리명 대소문자만 PostgreSQL에 맞춘다

- 상태: 채택
- 날짜: 2026-09-30
- 결정자: Youngki Ku

## 상황

명명 표준은 결정 대기 항목이었다(사내 표준용어사전 또는 공공데이터 공통표준용어). 「공공데이터베이스 표준화 관리 매뉴얼」(2026.4)을 검토한 결과([정리](../reference/public-db-standard-manual-notes.md)), 공통표준은 다음을 정해 둔다.

- 논리명: 표준용어명 = 표준단어의 조합이고, 마지막 단어는 형식단어다.
- 물리명: 표준용어 영문약어명(대문자, `_` 연결, 30자 이하).
- 타입·길이: 형식단어 → 표준도메인. 날짜는 `CHAR(8)`(YYYYMMDD), 일시는 `DATETIME` 또는 `CHAR(14)`다.

공통표준은 공공데이터포털에 CSV로 공개되어 있다([data/standards/](../../data/standards/README.md)). 기관표준도 공통표준을 준용해야 하므로 사내 표준용어사전을 쓰더라도 공통표준이 기반이 된다.

그러나 공통표준은 특정 DBMS를 전제하지 않는다. PostgreSQL에 그대로 옮기면 두 가지가 불편하다.

1. 날짜를 문자로 저장하면 날짜 연산·비교를 할 때마다 형변환이 필요하다. pgxnl이 이 스키마로 SQL을 생성할 때도 불리하다.
2. PostgreSQL은 따옴표 없는 식별자를 소문자로 바꾼다. 대문자 물리명을 유지하려면 모든 SQL에 따옴표를 붙여야 한다.

## 결정

명명과 타입은 공통표준을 따른다. 다만 아래 두 가지는 PostgreSQL에 맞춘다.

**1. 날짜·일시 도메인은 PostgreSQL 네이티브 타입으로 바꾼다.**

| 공통표준도메인 | 공통표준 타입 | nlxpg 타입 |
| --- | --- | --- |
| 연월일C8 | CHAR(8) | `date` |
| 연월일시분초D | DATETIME | `timestamp` |
| 연월일시분초C14 | CHAR(14) | `timestamp` |
| 연월일시분C12 | CHAR(12) | `timestamp` |
| 연도C4, 연월C6, 월C2, 시분C4, 시분초C6 | CHAR | 그대로 `char(n)` |

연도·연월처럼 날짜의 일부만 표현하는 도메인은 PostgreSQL에 맞는 타입이 없어 공통표준을 그대로 따른다.

**2. 물리명은 공통표준 영문약어명을 소문자로 쓴다.** 예: 거래처명 `CNPT_NM` → `cnpt_nm`. 따옴표 없이 쓸 수 있다.

그 밖의 도메인은 공통표준을 그대로 따른다.
- 여부C1은 `char(1)`에 'Y'/'N'을 쓴다(`boolean`으로 바꾸지 않는다).
- 길이는 공통표준 값을 그대로 쓴다. 공통표준은 바이트 기준(한글 2바이트)이고 PostgreSQL `varchar(n)`은 문자 수 기준이라 실제로는 여유가 더 생긴다.

속성명을 물리명·타입으로 바꾸는 순서:

1. 공통표준용어에 있으면(이음동의어 포함) 그 용어의 영문약어명과 도메인을 쓴다.
2. 없으면 표준단어로 분할해 단어 영문약어를 `_`로 잇고, 마지막 형식단어의 도메인분류에서 도메인을 고른다. 이렇게 만든 용어는 DB표준 후보로 표시한다.
3. 단어로 다 분할되지 않으면 비표준으로 표시하고, 추출 단계의 영문명과 타입 힌트를 쓴다.

테이블명도 엔터티명을 표준단어로 분할해 같은 방식으로 만든다. 테이블 명명규칙은 매뉴얼상 기관이 정하는 사항이라 공통표준에는 없다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| 공통표준 그대로 (`CHAR(8)` 날짜, 대문자 물리명) | 공공기관 산출물과 완전히 일치 | 날짜 연산마다 형변환, 모든 SQL에 따옴표 필요 | 미채택 |
| 공통표준 + 날짜·대소문자만 PostgreSQL에 맞춤 | 명명·도메인 체계는 유지하면서 PostgreSQL에서 자연스러움 | 공통표준 도메인과 타입이 다른 컬럼이 생김(날짜류) | **채택** |
| 공통표준 미사용 (LLM이 영어 snake_case 제안) | 구현이 단순 | 공공기관 표준과 무관, 명명 일관성 없음 | 미채택 |

## 결과

- 공통표준 준수 여부를 판정할 때, 위 표의 날짜 도메인은 PostgreSQL 타입으로 바뀐 것을 준수로 본다. 산출물에는 원래 공통표준도메인명(예: 연월일C8)을 함께 남겨, 공통표준 형식으로 되돌릴 수 있게 한다.
- 평가에서 정답 스키마(BIRD 등)는 공통표준을 따르지 않으므로, 명명 준수율과 스키마 복원도는 따로 잰다.
- 공공기관에 산출물을 제출해야 하는 경우처럼 공통표준 원형 타입이 필요해지면, 도메인 → 타입 매핑만 바꾸는 설정을 추가해 다시 검토한다.
- 공통표준은 매년 11월 갱신된다. 실행 이력에 사용한 판(예: 20251101)을 기록한다.
