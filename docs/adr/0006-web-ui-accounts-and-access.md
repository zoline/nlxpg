# ADR-0006: 웹 UI 계정은 nlxpg 전용으로 두고, 관리자·사용자 2역할에 실행 이력은 본인 것만 보게 한다

- 상태: 채택
- 날짜: 2026-10-01
- 결정자: Youngki Ku

## 상황

웹 UI에 로그인이 없었다. 4단계 파일럿에서는 사내 문서를 올리게 되는데, plan.md §데이터 보안은 사내 문서를 "파일럿 참여자로 한정"하라고 한다. 원문·추출 결과·근거가 시스템 DB에 남기 때문이다. pgxnl은 이미 계정(admin/user, bcrypt 비밀번호)을 갖고 있다.

## 결정

- **계정:** nlxpg 시스템 DB에 따로 둔다(`nlxpg_users`). pgxnl 계정과 공유하지 않는다.
- **역할:** 관리자(admin)·사용자(user) 2단계. pgxnl과 같다.
  - 관리자: 사용자 관리, 시스템 정보, 모든 실행
  - 사용자: 설계·검증·검토, **자기가 만든 실행만** 보고 지운다
- **실행 이력 공개 범위:** 본인 것만. 남의 실행은 API가 404로 답해 존재 여부도 알리지 않는다. 원문 문서도 자기 실행이 쓰는 것만.
- **첫 관리자:** 사용자가 없을 때 서버가 `admin`을 만든다. 초기 비밀번호는 `NLXPG_ADMIN_INITIAL_PASSWORD`, 없으면 무작위로 만들어 서버 로그에 한 번 남긴다. 관리자가 만든 계정·초기화한 비밀번호도 첫 로그인 때 바꾸게 한다.
- **구현:** 비밀번호는 표준 라이브러리 scrypt 해시(새 의존성 없음). 세션은 무작위 토큰을 HttpOnly 쿠키로 주고 DB에는 SHA-256 해시만, 12시간.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| pgxnl 계정 공유 | 계정 관리 한 곳 | nlxpg가 pgxnl DB의 비밀번호 해시를 읽어야 하고 두 앱이 묶임 | 미채택 |
| nlxpg 전용 계정 | 앱이 독립, 권한 경계가 분명 | 계정을 두 번 관리 | **채택** |
| 실행 이력 모두 공유 | 협업이 쉽다 | 사내 문서 원문이 다른 사용자에게 보임 | 미채택 |
| 공개 문서는 공유, 사내 문서만 제한 | 협업과 보안의 절충 | 문서마다 구분을 정확히 해야 함 | 미채택 |
| 본인 것만 (관리자는 전부) | 가장 단순하고 안전 | 서로의 결과를 보려면 관리자를 거쳐야 함 | **채택** |
| 관리자·설계자·검토자 3역할 | 검토 전담자 구분 | 지금 규모에 과함 | 미채택 |

## 결과

- 사용자 도입 전에 만든 실행(만든 사람이 NULL)은 관리자만 본다.
- 다른 사람의 결과를 검토(사람 검토 점수)하려면 지금은 관리자 계정이 필요하다. 검토 전담자가 생기면 "공유" 기능이나 3역할을 다시 검토한다.
- 표준 검증의 "DB 접속" 탭은 로그인한 사용자 누구나 서버에서 임의의 DB에 접속하게 한다. 사내망에서는 문제가 될 수 있어, 필요하면 관리자 전용으로 바꾼다.
