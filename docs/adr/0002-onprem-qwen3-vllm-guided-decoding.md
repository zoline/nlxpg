# ADR-0002: 온프레미스 Qwen3와 vLLM guided decoding으로 구조화 추출

- 상태: 제안 (사내 문서가 아닌 실행의 외부 API 예외는 [ADR-0008](0008-external-llm-for-non-internal-documents.md))
- 날짜: 2026-09-30
- 결정자: 

## 상황

파이프라인의 핵심은 문서에서 엔티티·속성·관계를 구조화된 형태로 뽑아내는 단계다. 입력은 사내 문서이므로 외부 API로 내보내기 어렵다. 팀은 이미 온프레미스 GPU 환경에서 vLLM으로 모델을 서빙하고 있고, pgxnl에서 Qwen3 계열을 BIRD로 평가한 경험이 있다.

한편 Doc2DB-Bench의 추출 과제 결과에서 오픈 모델과 상용 모델의 격차가 크게 나타났다(전체 F1 기준 Qwen2.5-72B 36.07, GPT-5.4 75.25). 과제는 다르지만, 오픈 모델로 복잡한 구조화 작업을 할 때 성능 보완책이 필요하다는 신호다.

## 결정

구조화 추출은 온프레미스 Qwen3 모델을 vLLM으로 서빙하고, guided decoding으로 JSON Schema 형식을 강제해 수행한다. 한 번에 전체 스키마를 만들게 하지 않고, 추출·정합·모델링 단계로 나누어 호출한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| 상용 클라우드 API | 현재 최고 수준의 성능 | 사내 문서 반출 불가, 비용 | 미채택 |
| 온프레미스 오픈 모델 + 자유 형식 출력 | 구현이 단순 | 형식 오류와 후처리 부담 | 미채택 |
| 온프레미스 오픈 모델 + guided decoding + 단계 분해 | 데이터가 내부에 머묾, 형식 오류 제거, 기존 인프라 재사용 | 단계별 프롬프트와 스키마 설계 비용 | **제안** |
| 추출 전용 모델 파인튜닝 | 특정 도메인 성능 향상 가능 | 학습 데이터 구축 부담 | 추후 검토 |

## 결과

- 추출 결과는 항상 정의된 JSON Schema를 따르므로 후속 단계를 결정적으로 구현할 수 있다.
- 추출용 JSON Schema(엔티티, 속성, 값 예시, 관계, 카디널리티)의 설계가 첫 번째 핵심 산출물이 된다.
- 베이스라인 점수가 목표에 크게 못 미치면 모델 크기 변경이나 파인튜닝을 다시 검토한다.
