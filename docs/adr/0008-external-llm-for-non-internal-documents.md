# ADR-0008: 사내 문서가 아닌 실행에는 외부 LLM API(Claude)를 골라 쓸 수 있다

- 상태: 채택
- 날짜: 2026-10-01
- 결정자: Youngki Ku

## 상황

ADR-0002는 사내 문서를 밖으로 보내지 않으려고 온프레미스 모델만 쓰기로 했다. 그런데 공개 문서나 테스트용으로 만든 문서로 설계 품질을 시험할 때는 반출 문제가 없다. 이런 실행에서는 상용 모델(Claude)로 돌려 온프레미스 모델과 결과를 비교하고 싶다. ADR-0002가 인용한 Doc2DB-Bench에서도 오픈 모델과 상용 모델의 격차가 컸다.

새 설계에는 이미 "사내 문서" 체크가 있고, 문서마다 보안 구분(`nlxpg_documents.classification`: public / internal)을 기록한다.

## 결정

- LLM 프로필 제공자에 `anthropic`(Claude, 공식 `anthropic` SDK)을 추가한다. 패키지는 선택 설치(`pip install -e '.[claude]'`)로 둔다.
- 외부 API 프로필은 다음과 같이 쓴다.
  - **문서 추출(기본) 역할에 지정할 수 없다.** 따라서 기본 설정으로는 외부로 나가지 않는다.
  - 새 설계에서 모델을 직접 골랐고 **"사내 문서"가 꺼져 있을 때만** 쓴다. 화면이 막고, 서버(`POST /api/runs`)도 400으로 거절한다.
  - 테스트 문서 작성 역할에는 지정할 수 있다. 합성 문서를 만들 뿐 사내 문서를 보내지 않는다.
- 실행 설정(`nlxpg_runs.config`)에 `llm_profile`과 `external_api`를 남긴다. 실행 상세에는 "외부 API" 표시가 붙는다.
- 구조화 출력은 `output_config.format`(json_schema)로 강제한다. 기본 모델은 `claude-opus-5-5`다.
  - temperature는 보내지 않는다(Opus 5.5에서는 거부된다).
  - 역할의 "생각 끄기"는 effort=low로 대신한다.
  - 안전 분류기 거절에 대비해 서버 측 fallback(`fallbacks: "default"`)을 켠다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택 여부 |
| --- | --- | --- | --- |
| 외부 API 계속 금지 | 반출 위험 없음 | 공개 문서로도 상용 모델과 비교할 수 없음 | 미채택 |
| 테스트 문서 작성 역할에만 허용 | 반출 위험 없음 | 설계(추출) 품질을 Claude로 비교할 수 없음 | 미채택 |
| 사내 문서가 아닌 실행에서 골라 쓰기 | 공개·테스트 문서로 비교할 수 있고, 기본값은 온프렘 유지 | 사용자가 "사내 문서" 체크를 빠뜨리면 사내 문서가 나갈 수 있음 | **채택** |
| 모든 역할에 허용 | 가장 단순함 | 사내 문서 반출 | 미채택 |

## 결과

- "사내 문서" 체크는 사용자의 판단에 의존한다. 외부 모델을 고르면 화면에 경고를 띄우고 체크를 잠근다. 사내 문서를 다루는 서버라면 관리자가 외부 프로필을 등록하지 않으면 된다.
- Anthropic API 키는 다른 키처럼 `NLXPG_SECRET_KEY`로 암호화해 DB에 둔다(ADR-0007).
- 서버에서 api.anthropic.com으로 나가는 인터넷 연결이 있어야 한다.
- ADR-0002의 온프레미스 원칙은 사내 문서에 대해 그대로 유지된다.
